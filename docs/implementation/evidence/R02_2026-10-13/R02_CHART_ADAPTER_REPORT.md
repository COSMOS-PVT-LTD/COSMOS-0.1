## Interface and behavior

UMD browser globals: `window.ScientificChart` class alias and `window.CosmosScientificChart` exports. CommonJS exports: `ScientificChart`, `validatePlot`, `extremaDecimate`, `ChartError`, `LIMITS`.

`ScientificChart(container, echarts=globalThis.echarts)` is lazy; `setData(plot,{xScale:'linear',yScale:'linear'})` validates/copies/freezes actual source data before rendering via the locally provisioned ECharts SVG renderer. It returns immutable rendering/provenance metadata. `resize()`, `resetZoom()`, idempotent `dispose()`, and subsequent valid `setData()` reuse are supported. An invalid scale/source update clears/disposes previous marks and removes export eligibility; stale prior content cannot remain presented as the new curve.

Axes require quantity and units; scales are explicitly linear/log. Log axes reject every nonpositive source value rather than dropping/clipping/replacing it. Points accept only actual finite numbers, not booleans, strings, null, holes or nonfinite values. Missing/empty/error states are typed and explicit. Invalid source updates clear chart state before renderer disposal, so even a renderer teardown exception cannot preserve stale export eligibility.

The actual backend source contracts are distinct, not mapped into fabricated common identities:

- `domain:'propulsion'` requires actual `design_id`, safe nonnegative integer `revision`, `result_id`, original `content_sha256`, `status:'CURRENT'`, and recorded `model_id` string **or null**. Original structured `verification`/`validation` status/reference objects and full `validity` status/checks/violations/range object are required and retained unchanged. If present, freshness must be `current`. No simulation run/study identity is invented or accepted in this variant.
- `domain:'simulation'` requires actual `run_id`, `study_id`, original `content_sha256`, `status:'completed'`, `freshness:'current'`, real nonempty `model_id`, original verification/validation/convergence strings, conservation object and source-reference array. Each supplied reference retains its path/hash and other bounded JSON metadata. The existing model is `steady-spherical-conduction-v1`; the adapter does not substitute a model label or pretend it has a propulsion design/revision/result identity.
- All original additional bounded JSON, including the complete canonical `source_record` supplied by the backend, is cloned/frozen without flattening or dropping nested provenance. Structured status values (including unknown/not-claimed/not-performed) are never promoted by successful rendering. Identity/hash declarations are preserved, not authenticated or independently recomputed by this renderer; backend provenance verification remains authoritative.

Extrema reduction retains endpoints plus x/y minima/maxima per ordered bucket, preserving global extrema and source order. Entire displayed plot stays below 2,000 points across all series. Reduction is display only and declared in returned metadata and accessible chart description; exact source rows remain the root view's responsibility. Source points/rows are immutable copies, not solver-owned state or inferred provenance. No smoothing or scientific interpolation is applied by the adapter.

ECharts tooltip uses `renderMode:'richText'`, not unsanitized HTML; point values carry explicit axis units. Computed/reference series differ by solid/dashed lines and filled/open markers as well as semantic colors. Existing CSS theme tokens supply typography and colors, with restrained dark defaults. Inside/slider zoom, pan and reset toolbox/action preserve original data; root's HTML controls and exact table provide keyboard/export integration. This is not a complete screen-reader or grayscale qualification claim.

`exportSVG()` returns `{dataURL,metadata}` using `chart.getDataURL({type:'svg'})` and requires actual SVG output. Its immutable sidecar adds `view`: actual bounded current zoom-component indices/type/filter/axes/percent/value/range-mode fields from `getOption().dataZoom`, or an explicit unavailable state if the renderer exposes no state. It never invents a full-range window. Source metadata remains identical; base/CSV metadata is not mutated by SVG export. Visible SVG title subtext now has two compact 12px lines: unquantified uncertainty plus actual source status, and preliminary-model/radial-benchmark boundary plus no physical validation. The full title remains accessible even where bounded visible-title width requires ellipsis. Legend/grid top offsets reserve caption separation; actual browser narrow/compact layout qualification remains the root workstream's responsibility.

`exportCSV()` returns `{csv,metadata}` containing **all exact source points as parsed by JavaScript**, not reduced/zoomed display points. CSV identity headers are domain-specific: propulsion design/revision/result versus simulation run/study/freshness. `model_id_json` preserves the recorded string or null. Structured verification/validation/validity or convergence/conservation/source references are JSON-serialized, not converted to `[object Object]` or abbreviated claims. `*_json_first_row` headers explicitly mean metadata appears once in the first data row; complete `source_json_first_row` includes all original source fields/record. Remaining source-point rows keep identity/hash/status/model/uncertainty columns but leave those metadata cells empty. This avoids repeating an entire source dataset per point and making export size quadratic. Text formula prefixes are neutralized and quotes/newlines CSV-escaped; negative numeric measurements remain numeric. JavaScript numeric CSV/source-record reserialization does not claim byte-identical Python number spelling. Metadata is an export sidecar, not a new source/certificate.

Exact original canonical bytes are carried as backend `source.source_canonical_json`: the authoritative Python JSON text used for its digest, retained literally in copied source metadata and CSV/SVG sidecars. Only that exact root path may exceed the ordinary 8,192-character string bound, within the whole 8 MiB serialized UTF-8 budget. Arbitrary or nested same-name fields do not gain the exception. It must parse as bounded finite JSON and agree semantically with `source_record` when supplied. The adapter does **not** hash a JS reserialization to replace the source digest; consumers can hash the UTF-8 bytes of the exact preserved canonical string. Equivalent numeric spelling/key order may change JS serialization, but never alters that exact text.

No confidence band is manufactured: this contract has no reviewed uncertainty bounds and accepts only `uncertainty:'not quantified'`. Source status/verification/validation are preserved, not upgraded by a successful chart render or export. Display bounds: 200,000 total source points/rows, 16 series, 1,000,000 JSON nodes, depth 24 and 8 MiB serialized display boundary. Escaped JSON UTF-8 bytes are charged incrementally per code point during cloning, including controls/surrogate pairs, before output copies exceed the budget; ordinary key/text lengths are capped at 8,192 characters, with only the exact canonical-text exception described above. There is no large intermediate `JSON.stringify`/`TextEncoder` allocation to assess that long field. Arrays are checked against remaining node capacity before copying/accessing entries; objects are cloned incrementally without eager entry-map allocations. Bounds reject the complete payload rather than truncate provenance. Literal prototype-like JSON keys are preserved as own data properties without prototype mutation. A read-only peer review identified the earlier post-clone allocation weakness; it was fixed and covered by permanent budget/getter/prototype regression tests before handoff.
