# ADR: additive, separately qualified PicoGK component generator

Date: 2026-10-24. Authority: user requested PicoGK geometry generation and authorized implementation. R08 remains on hold. This is an R07 geometry extension, not a replacement of frozen module layering or a production/hardware release.

## Decision

Retain the existing saved component model as dimensional intent. Derive a distinct `implicit_field` feature graph and execute COSMOS-owned signed-CSG recipes in a separate headless PicoGK process. The native library renders those fields directly; it does not import an OCCT tessellation. Retain named VDB fields and metre-encoded STL, with per-part source identity and independently checked mesh results. OCCT remains available separately for analytic BREP/STEP, exact solid inspection and draft drawings. No arbitrary implicit-to-analytic-STEP conversion is claimed.

Opt in through `COSMOS_PICOGK_COMPONENT_CONFIG`, behind existing NGG admission. Require a new source/runtime-byte-bound software receipt. Never rewrite the broken historical combined runtime's receipts or pretend its generic G5 evidence is restored. The old reference fixture laboratory remains disabled under the component profile. Separately qualifying current OCCT methods preserves its own admission contract; `picogk_enabled:false` in that OCCT-only manifest does not disable this independently admitted PicoGK service.

## Runtime restoration and provenance

Persistent, ignored location: `.runtime-picogk/2026-10-24-v1/`. Use official Microsoft .NET SDK 9.0.318 for macOS arm64 (runtime 9.0.20) and PicoGK 2.2.0 managed-source basis `7b30d22f7b550175962e478f626384cd7ab15411`. Native library and managed PicoGK assembly were recovered only after exact verification against the previous source-built runtime's recorded hashes. Relocate the native dependency search path on the **new copy only**, ad-hoc sign that copy, and retain restoration provenance. Compile the COSMOS component worker from repository source. No global SDK, owner data root or historical manifest is modified. Local research qualification is not distribution/signing/SBOM approval.

The verified SDK download archive was removed after extraction to recover disk space; the installed SDK/runtime remains. `scripts/prepare_picogk_runtime.py` refuses binary overwrites. Its restoration provenance and exact hashes, not transient download files, bind the new qualification.

## Numerical and topology policy

Require explicit voxel spacing (25 micrometres to 2 millimetres) and explicit volume, centroid, forward-residual and reverse-distance QA criteria with applicability source. Those are software-study criteria, not manufactured tolerances. Reject requests exceeding 120 million estimated field cells; cap the mesh at 4 million triangles and individual originals at 256 MiB. Preserve the existing smaller OCCT/fixture defaults.

The native zero-isosurface initially produced disconnected, coplanar fragments on the grid-aligned pintle tip cap. This was rejected by independent component count, edge incidence and Euler checks. Canonicalize the sign only for residuals within `64 * double machine epsilon * max(1, source bound magnitude in mm)`, assigning positive sign to numerically zero samples. Report that bound in every receipt and verify it against source bounds. This is not a voxel offset, feature resizing, smoothing, mesh welding or acceptance-tolerance relaxation. The exact recipe residual outside this arithmetic tie envelope is unchanged. Keep explicit regressions at multiple grid spacings.

STL encoding removes only exactly zero-area faces **after** float32 metre conversion, per part. Record removal counts; leave surviving vertices unchanged. This distinct component policy does not adopt the old fixture policy's degenerate-face fraction as dimensional acceptance. Independently require a single connected closed oriented mesh per source part, correct expected Euler characteristic, no duplicated/zero-area triangles, positive volume, bounds/integral comparisons, sampled forward CSG residuals and reverse point-to-triangle distances. These checks are not certified Hausdorff distance, general self-intersection certification, pressure integrity, CFD or experimental validation.

## UI and authority

Project-authorized durable commands capture exact current saved model/head, derived graph, SI request, runtime bytes, explicit QA and operation identity. Preserve history, cancellation, retries and source freshness checks. Disable BREP-only metrology/drawing controls on PicoGK previews. Existing shared axes, projections, sections, exploded view, colours and reference measurements remain presentation tools, with representation boundaries visible.

### Large-model display qualification

The initial triangle-sampled LOD was visibly perforated and is rejected/removed. A `vtkDecimatePro` trial passed small examples but failed independent checks on the actual assembly; its setting name is not accepted as evidence of encoded topology. Use the already installed VTK9.3.1 in an isolated, separately pinned display process, not in the GUI and not for PicoGK field generation. Final candidate method: volume-preserving quadric decimation, double-coordinate input and square-root per-part allocation within the existing 200k-triangle viewport envelope. Recheck every reduced part against the captured source geometry and explicit software criteria; never silently increase those tolerances or substitute the preview for originals.

The actual full assembly exposed one dangling single-triangle flap from reduction. The display encoding may remove only the exact combinatorial case with two one-face boundary edges, one three-face edge and a vertex referenced by that triangle alone. No area epsilon, welding, smoothing or hole filling is used. Record every removal and independently require closure, connectivity, orientation, expected Euler characteristic and dimensional checks afterward. This **display-only** cleanup does not alter the original native VDB/STL or change their stricter encoding policy.

Generate/check large previews during the cancellable background build and retain `preview.f32` and `preview.json` as checksum-bound diagnostics alongside the original VDB/STL. Do not perform long native simplification in a synchronous GET, and do not fall back to triangle discarding if reduction cannot pass. The VTK method is documented by [VTK9.3 quadric decimation](https://vtk.org/doc/nightly/release/9.3/html/classvtkQuadricDecimation.html); its volume-preservation setting is an algorithm option, not a certification. Physical and manufacturing validation remain NOT_PERFORMED.

The first integrated large-preview attempt was rejected by the existing 1GiB supervised-process ceiling. Streaming parts and narrowing object lifetimes alone were insufficient: the 1,767,080-face cooled chamber exhausted the budget during quadric reduction. A zero-absolute-error prepass retained 1,719,708 faces and also exceeded the budget. Preserve the failed evidence; do not raise that resource ceiling or any dimensional/topology acceptance criterion. For parts above 800,000 faces, use a display-only `vtkDecimatePro` prepass targeting 600,000 faces, with the absolute-error algorithm option set to 1e-7 metre, topology preservation enabled, splitting disabled, boundary deletion disabled and double-coordinate output. Release its original mesh before quadric reduction. This is a display algorithm choice, not proof of exact preservation or a certified distance bound: every final encoded part must still pass the unchanged independent source checks. The [VTK DecimatePro documentation](https://vtk.org/doc/nightly/html/classvtkDecimatePro.html) explains these settings and explicitly does not guarantee the requested reduction under such constraints. Qualification therefore includes the actual 16-part workload under the same supervisor; small fixtures alone are insufficient.

Qualification and browser demonstration use a separately copied task data root with online SQLite backups and integrity checks. Do not restart the user's current viewer or switch/migrate live data. No commit, push, R08 transition, manufacturing release or hot-fire approval is authorized by this implementation task.
